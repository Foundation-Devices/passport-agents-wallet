# gui-app-nunchuk-signer

A KeyOS proof-of-concept: **Passport Prime as a self-custodied, hardware-enforced
spending-policy co-signer for an AI agent's Nunchuk wallet.** An agent runs the
wallet via `nunchuk-cli`; Prime holds one key and gates spending on-device. Small
spends sign **unattended** (HSM mode); spends over your limits need a tap on Prime.

This is the self-custodied analog of Nunchuk's Platform Key, and a drop-in for
their `nunchuk-coldcard-hsm` agent-skill with `ckcc` replaced by `prime-signer`.

## Two treasury models (chosen at onboarding, on-device)

- **Self-custodied (2-of-2):** `wsh(or_d(multi(2, agent, prime), and_v(v:pk(prime), older(N))))`.
  Agent + Prime co-sign; Prime enforces the policy. Recovery branch lets Prime
  spend **alone after N blocks** if the agent key is lost. Fully sovereign.
- **Cloud-assisted (2-of-3):** adds Nunchuk's always-online **Platform Key** as a
  third signer, so the agent keeps spending while Prime is off. Prime stays
  sovereign: `agent + Prime` is a valid 2-of-3 that never needs Nunchuk. (A plain
  2-of-3 has no separate Prime-only timelock branch — it self-recovers via any 2 of
  the 3 keys; the `older(N)` recovery branch is a 2-of-2 feature. See `docs/ARCHITECTURE.md`.)

## The policy gate (`src/nunchuk/gate.rs` + `history.rs`)

Prime decides, per PSBT, whether to release its signature:
- `max_amount` (per-tx), rolling **velocity** caps (daily/weekly), and clock-free
  **session/lifetime** backstops that survive reboot.
- Under every cap → **auto-sign, no human**. Over any cap → on-device approval.
- The append-only ledger (debited **before** signing) powers velocity + the
  Activity screen. See the plan's "Velocity enforcement & the clock problem".

Recovery-path spends always require approval (never auto-signed).

## Architecture

- Bitcoin/PSBT/policy logic in `src/nunchuk/` on `ngwallet::bdk_wallet::{bitcoin,
  miniscript}` (compiles for host sim + `armv7a-unknown-xous-elf`).
- UI: Slint, pages under `ui/pages/*`; router in `ui/gen/*` generated by `build.rs`.
- Device key: `security.app_seed()` → master `Xpriv` → BIP48 `m/48'/1'/0'/2'` (tpub).
- Network: **testnet** (what nunchuk-cli supports; shares `tb`/`tpub` with signet).
- Host layer in `host/`: **`prime-usb`** (the device-talker over USB-CDC, for real
  hardware), `prime-signer` (the simulator file-bridge equivalent), `skills/prime-hsm/SKILL.md`
  (the agent-skill runbook), `hwi/prime_hwi.py` (HWI driver skeleton, see `docs/HWI.md`).
  All Bitcoin work (keys, PSBTs, signing, broadcast) is `nunchuk-cli`'s job; the host
  tools only carry keys/descriptors/PSBTs to and from the device.

## Run (hosted simulator)

```
cd ../..        # the KeyOS checkout root
AR_armv7a_unknown_xous_elf=arm-none-eabi-ar cargo xtask run --hosted
```

Open **Nunchuk** from the launcher → onboarding choice (Self-custodied / + Platform
Key) → "How it works" explainer (pick the recovery timelock) → Continue. Then:
**Sign PSBT** (auto-signs the demo in policy), **Policy** (spend caps + paths + keys),
**Activity** (signing log), **Export key for Nunchuk** (xpub for `nunchuk-cli`).

Dev: `PRIME_DEV_AUTOSEED=selfcustody|platform` seeds a treasury + drops a demo PSBT
so the HSM auto-sign loop runs headless (sim-only, never on device).
